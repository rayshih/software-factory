Turn your engineering backlog into verified, review-ready pull requests — with controlled execution, visibility, and human approval.

Coding agents can already write code. What teams lack is the factory around them: a queue, execution control, failure recovery, CI verification, human review, an audit trail and cost visibility. Software Factory is that control layer — built by integrating existing infrastructure, not by building another agent.

01 — How it works

Issue in. Review-ready pull request out.

A labelled GitHub issue enters through a GitHub App. The control plane stores it. Trigger.dev queues it, with concurrency limits and retries. An Anthropic Managed Agent works in a sandbox. The run opens a branch and a pull request, GitHub Actions runs CI, and a person reviews the result.

GitHub Issue → GitHub App / webhook → control plane (Postgres) → Trigger.dev queue → Anthropic Managed Agents sandbox → branch + PR → GitHub Actions CI → human review

  1. 01

    GitHub Issue

    A labelled item from the backlog.

  2. 02

    GitHub App

    Webhook in. Tasks are persisted idempotently.

  3. 03

    Control plane Being built

    Postgres. Decides when a task runs, and records state, cost and failures.

  4. 04

    Trigger.dev

    Queue, global and per-repo concurrency, retry.

  5. 05

    Managed Agents

    Anthropic session and sandbox. Timeouts included.

  6. 06

    Branch + PR

    One pull request per task. Retries do not open a second one.

  7. 07

    GitHub Actions

    CI verification before anyone is asked to review.

  8. 08

    Human review Always

    Approve, request changes, or reject.

Requesting changes sends the task back through the queue. Rejecting it closes the task and records the failure. Approving it accepts the pull request. Nothing merges on its own. An idle agent session is not a completed task.

03 — Principles

What it will respect, and what it will not do.

Principles

  1. Integrate existing infrastructure; don't rebuild it.
  2. Decouple the agent runtime from the control plane.
  3. Idempotency on every external operation.
  4. Retries never create duplicate pull requests.
  5. An idle agent session is not a completed task.
  6. Every pull request is human-reviewed.
  7. Record cost, human interventions and failure causes.
  8. Never run on unauthorised repositories.

Not in this experiment

  • SaaS onboarding
  • Billing
  • RBAC / SSO
  • Multi-tenancy
  • A custom agent harness
  • A custom scheduler
  • Multi-model routing
  • Auto-merge
  • Deploy automation
